# 长期维护计划

本计划以真实质量和真实用户反馈为目标，不以虚构下载量、Star、Issue、贡献者或申请资格为目标。

## 每次变更

- 每个计算逻辑或 Excel 行为改动都补充自动化测试；版本说明记录用户可见的变更。
- 在 Windows 上验证 Python 源码运行；涉及 UI 时检查布局与交互；涉及 Excel 时使用合成文件验证导入、导出及回读。
- 合并前检查依赖、隐私边界、开源许可和打包路径；不加入未说明的遥测、自动上传或客户数据。

## 发布节奏

- 以语义版本区分修复、兼容功能和破坏性变更，维护 `CHANGELOG.md`。
- 每次发布重跑测试和依赖审计，重建便携 EXE，记录构建环境、SHA-256、已知限制及第三方通知。
- 仓库包含 Windows GitHub Actions 自动测试工作流；首次公开后确认首个云端运行通过，再将 CI 记作已验证的维护保障。
- 仅在实际验证后发布兼容性、速度、运输规则或安全性声明。

## Issue 与反馈

- 使用 Issue 表单收集版本、复现步骤和预期结果；提醒报告人只用合成数据。
- 先判断是否可复现，再分类为 Bug、功能建议、文档或兼容性问题；注明未解决的限制，避免静默关闭。
- 每月至少一次查看未处理事项；如果项目无人使用或没有新维护活动，照实记录，不制造活动。

## 真实维护证据

保留发布标签、通过的 CI 运行、真实修复的 Issue/PR、版本说明、用户自愿提供的非敏感反馈和实际使用场景。公开展示用户反馈前，先征得反馈提供者许可并去除个人与商业敏感信息。所有公开的维护、使用和兼容性数据都应保留可复核证据，不预先声称任何外部计划资格。
